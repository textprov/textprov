TextProv

Text that carries labels about its origin: human-written, AI-generated, mixed, edited, or unknown. TextProv is an open protocol for keeping those labels in the text itself, rather than in a separate file or one application's metadata.

Use it in an editor or content pipeline to label what you know about the text. The labels can travel through copy, paste, and plain-text storage, as long as the receiving software preserves the marks.

A label is a claim, not proof. TextProv does not detect AI writing or verify authorship. Anyone can add, change, or remove marks; unmarked text does not mean human-written.

What travels with the text?

TextProv adds normally invisible Unicode characters called variation selectors after the letters or symbols being labelled. A TextProv reader recognizes these marks and can show their meaning using underlines, colours, or other decorations.

A code point is a number identifying a character in Unicode. For example, U+0041 identifies A. TextProv uses U+E0101 as the AI label:

U+0041  U+E0101
   A    AI mark

Unicode defines the characters; UTF-8 encodes them as bytes in a file or message. TextProv is not a replacement for UTF-8. A UTF-8 file can store both the letters and their marks; older encodings such as Latin-1 cannot store these marks.

These label meanings are a TextProv convention, not Unicode-registered variation sequences. Software that does not understand TextProv usually shows the ordinary letters. Software that strips invisible characters can remove the labels, so test the path your text takes.

Use it

Python: mark a file and read it back

Requires Python 3.9+. Run these commands in a terminal on macOS or Linux. They create an isolated environment, install TextProv from PyPI, and write a marked UTF-8 file.

python3 -m venv .venv
.venv/bin/python -m pip install textprov
printf 'Hello from TextProv.\n' > draft.txt
.venv/bin/python -m textprov -o marked.txt mark --ai draft.txt
.venv/bin/python -m textprov inspect marked.txt

The report identifies AI-marked text even if your editor shows no decoration. Open marked.txt and paste its contents into the reader above to see the label.

In Python code, marking and rendering are separate operations:

import textprov

marked = textprov.mark("Hello", state="ai")
print(textprov.to_html(marked))
print(textprov.strip_marks(marked))  # Hello

JavaScript: display existing marks

The npm package reads marks; it does not add them. Install it in your web project:

npm install textprov

With a bundler that supports CSS imports, render a container after adding its text:

import textprov from "textprov";
import "textprov/textprov.css";

const preview = document.createElement("p");
preview.textContent = "A\u{E0101}"; // A followed by the AI mark
document.body.append(preview);
textprov.render(preview);

The result is an AI-labelled A, styled without a special font. The reader wraps marked text in HTML spans with a data-prov attribute. The bundled CSS is optional; applications can choose their own presentation.

Ruby: mark, read, and render

The Ruby implementation provides the same core operations and a CLI. Requires Ruby 3.2+. To try the source without relying on a published gem:

git clone https://github.com/textprov/textprov.git
cd textprov
ruby -I ruby/lib -r textprov -e 'puts Textprov.to_html(Textprov.mark("Hello", state: "ai"))'

This prints HTML containing an AI-labelled span. Ruby API and CLI reference →

These are regular-weight Latin-text subsets from our Nerd Fonts fork, not full replacement fonts. They include Human and AI variants only. Mixed, edited, and unknown labels are displayed by the browser reader, not these fonts. Installing a font alone does not label any text.

The source fonts' older third selector has a different meaning from TextProv v1, so it is deliberately excluded from these subsets. See the font build notes and attribution or the font and interchange guide.

Font display depends on the application's text-rendering engine. The project's tests found that HarfBuzz displayed the selector variants while macOS CoreText did not. Keep selector-encoded text for sharing; the guide's private-use (PUA) samples require a matching font and are for controlled local experiments.

Implement the protocol

The project is early-stage; version 1 of the protocol is treated as stable. Start with the specification for label meanings and encoding rules, the code-point registry for the assigned marks, and the conformance fixtures to check your implementation.
