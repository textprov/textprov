Origin labels that travel with text

TextProv is a draft specification for marking the origin of individual characters within prose. Start with one person and one AI: keep track of text from each as passages are copied, combined, and reused.

A small shared vocabulary, carried in the text itself. Applications choose how to display and use it.

Copy the file to your clipboard

Run the command for your system to copy the same UTF-8 passage, then paste it into another app or the reader below. These commands replace your current clipboard contents.

macOS (Terminal)

curl -fsSL https://textprov.org/samples/marked-text.txt | LANG=en_US.UTF-8 pbcopy

Windows (PowerShell) — decode UTF-8 explicitly to preserve the marks.

[System.Text.Encoding]::UTF8.GetString((Invoke-WebRequest -UseBasicParsing 'https://textprov.org/samples/marked-text.txt').RawContentStream.ToArray()) | Set-Clipboard

Linux (Wayland) — requires curl and wl-copy from wl-clipboard.

curl -fsSL https://textprov.org/samples/marked-text.txt | wl-copy

Linux (X11) — requires curl and xclip.

curl -fsSL https://textprov.org/samples/marked-text.txt | xclip -selection clipboard

Labels in your text

Waiting for text.

To mark your own text, use the encoder.

Marks record supplied labels; they do not detect AI writing or verify authorship. They travel where software preserves them.

A mark alongside each character

TextProv adds a normally invisible Unicode mark after each character being labelled. Copy a passage and its marks can come along, without a separate metadata file.

The encoding follows visible characters (grapheme clusters); spaces in this example are unmarked. These label meanings are a TextProv convention, not Unicode-registered variation sequences.

A small vocabulary to build on

TextProv has two provenance labels:

LabelCode pointDeclared origin
humanU+E0100Human-written
aiU+E0101AI-generated

Shared labels; application choices. A label has a common meaning across tools. How it looks, whether to show it, and how it affects an application’s behaviour are up to that application.

Unmarked text has no label. Labels do not identify a particular person or model, or assign a trust level.

For prose communicated between people. Source code files, including comments and docstrings, are excluded. Code snippets within prose may be marked. See the marking scope.

What is settled, and what is open?

Published code-point allocations remain reserved and will not be reassigned. Specification behaviour is experimental and may change before Stable.

Only human and ai are provenance states. Other variation selectors are ordinary non-TextProv text, not additional labels. Presentation and application policies remain integration choices.

See the draft’s state definitions and maturity policy.

Help shape the draft

Try it in a real workflow. Small experiments and specific questions will help make the next draft better.

  • Test a text journey. Where do marks survive copying, editing, and saving? Where do they disappear?
  • Discuss the vocabulary. What should happen when a person edits AI text, or several sources contribute?
  • Build an integration. Try marking and reading text in a prose editor, conversation, or content pipeline.
