Human-labelled text · AI-labelled text

A proposal for keeping track of what you wrote and what AI generated, using Unicode’s existing capabilities to embed invisible labels directly in text. Open encoding choices and working demonstrations.

A voice may represent a person, a model, or another source. Attribution records a supplied reference; it does not detect authorship or verify identity.

Text and a voice reference

Voice1, Voice2, and further references distinguish sources. Their descriptions and optional classifications are separate from the reference itself.

Voice0 represents unattributed characters: ordinary Unicode text, without an extra marker or an assumption about who wrote it.

The text unit, reference scope, copying behavior, and encoding are decisions to make. Explore the model.

Several mechanisms to evaluate

Variation selectors provide a useful demonstration of attachment and normally invisible rendering, but collide with legitimate Unicode variation sequences. Private-use markers permit a private convention, with harder display and cursor trade-offs.

Other candidates include interlinear annotations, tag characters, explicit run delimiters, and a proposed standardized mechanism. Existing controls also provide structural precedents; using them for attribution would need its own justification.

Compare the encoding candidates and evaluation criteria.

An experimental VS example

This retained demonstration uses the earlier human/AI labels. It shows text containing embedded marks rendering without special fonts. It does not implement the proposed voice-reference model.

Download the UTF-8 example. To inspect the retained implementations, see the experimental JavaScript, Python, and Ruby SDKs.

The selectors U+E0100 and U+E0101 are an experimental convention, not Unicode allocations for attribution. The decoder can misread a legitimate Japanese variation sequence, and stripping marks can remove a real glyph distinction. Preservation depends on the software used. Read the VS assessment.

Help resolve the open questions

Useful evidence includes copying an interior excerpt, preserving distinct references from different documents, rendering multilingual text, and checking editing and accessibility behavior.

Review the open decisions, then contribute observations or discuss alternatives in the GitHub repository.
